# Implementation

## Recording

`AttemptSession` attaches to BeatLeader's `ReplayRecorder` in the solo gameplay container. It keeps offsets into the recorder's frame, note, wall, height, and pause lists, so each saved snapshot covers the active segment from its start through its save boundary. A seek closes the current segment and starts another at the seek position. Pause, checkpoint, failure, completion, restart, and exit can save the captured attempt.

Harmony prefixes capture misses and bad cuts before Beat Saber processes the same event through its energy counter. Snapshot creation copies the frame list and mutable replay events, merges those immediate mistake records with BeatLeader's completed note events, and records map identity, speed, outcome, failure time, and mistake times. The replay metadata carries a copy of the attempt header for recovery.

## Replacement grace and storage

Each segment starts recording as soon as the recorder is available. The default grace period is five song seconds and can be set from zero to 120 seconds. While the grace remains, Cutback keeps the previous replay available and records the new frames in BeatLeader's live recorder. At the threshold, promotion releases the previous replay's memory references with constant time work. A later normal save publishes the active attempt.

Startup recovery reads the recent replay on a worker task. Snapshot encoding and file replacement run on a serialized background queue. Cutback writes and flushes a temporary file before replacing `latest.bsor`, then writes the matching `latest.json` index. The previous disk replay remains available through the promotion step until a save replaces it. Replay loading has a 512 MB file limit.

## Failure and replay entry points

When Beat Saber enters its native failure flow, `AttemptSession` records the failure time and lets the normal scene and recorder continue for half a real second. Beat Saber's audio clock freezes during the death effect. A late tick after BeatLeader's frame recorder copies each newly measured pose into an owned tail and timestamps it from elapsed real time at the segment's recorded speed. Native completion and the tail deadline share one finalization path, which captures the last measured pose before saving. The snapshot joins this tail to the full attempt and excludes note events generated by the failure teardown. Automatic replay then queues that local snapshot when replay on death is enabled and the failure was not an auto restart.

The failed results Replay button opens the saved local snapshot when the results screen belongs to that failed map. The original pause menu buttons keep their positions and actions. Cutback adds a separate button using BeatLeader's ReplayIcon above the native button row. During the replacement grace period, that action uses the protected previous replay. After promotion, it snapshots and reviews the active attempt.

The replay launches through BeatLeader's `ReplayerLauncher` and transport. Cutback keeps BeatLeader's native toolbar, time display, timeline, marker visuals, and replay controls enabled for the captured span. `TimelineMarkerNavigation` captures event times at the native `GenerateMarkers` hook and attaches invisible Buttons to the existing miss and bad cut X images. A click selects that event and seeks to the configured start time before it. The patch runs only for a local Cutback review.

The BeatLeader timeline stays on its existing layout and marker objects. The click handler enables raycasts on the existing marker image and uses a Button with no transition, so its appearance and dimensions stay with BeatLeader. The Button receives pointer down and up at the marker, which prevents the parent slider from treating the marker click as a drag. Other timeline input follows the native slider path.

BeatLeader normally extends No Fail replay playback to the end of the song. `LocalReplayBounds` uses the captured end for the native transport and timeline. BeatLeader retains its native start coordinate for scene prewarming and audio seek offsets. Initial focus stays within the captured frames. Captures also preserve BeatLeader's modifier values. `LocalReplayModifiers` restores these for local reviews independently of the selected leaderboard's cached score data. Older captures use the gameplay modifier map.

## Focus and playback speed

`ReviewPlan` uses the attempt's captured start and end as fixed bounds. Its focus moments include the mistake categories enabled in settings. Miss focus defaults on and bad cut focus defaults off. A recorded failure is always included and takes priority for initial focus. The start time before a mistake defaults to three seconds and is configurable from one to 15 seconds.

Automatic slow motion is enabled by default. For each selected moment, playback follows an exponential ramp from the recorded speed toward the chosen minimum over the configured slowdown duration. It reaches the minimum at the event and holds through the tail. The default slowdown is three seconds and the default minimum is 10 percent of the recorded speed. Minimum speed can be set from 5 to 50 percent. Explicit timeline selection seeks to the start time before that event and also becomes a slow motion event while automatic slow motion is enabled. Death clip looping is optional and defaults off.

`PracticeTiming` keeps the BeatLeader replay transport in charge during local replay and corrects the audio clock when replay speed changes or seeks. Beat Saber practice speed ranges from 5 to 200 percent. When PracticePlugin is present, Cutback lowers its practice speed minimum to 5 percent while its seek cleanup and map extension handling remain in use for live practice.

## Insta-fail replay reset

BeatLeader's `ReplayerScoreProcessor.HandleReprocessRequested` resets `_batteryLives` to four when replay playback rewinds. A local replay with `instaFail` uses the native single life energy display, so Cutback resets the counter to one to keep the energy counter aligned with that display. `ReplayEnergyReset` changes only the constant immediately following the `_batteryLives` field name in that one BeatLeader method. The helper returns one for an active local Cutback replay whose main replay has `instaFail` enabled and returns BeatLeader's original four in every other case. The transpiler requires exactly one matching instruction pair and throws a compatibility error when the installed method changes shape.

## Boundaries and attribution

This implementation targets Steam Beat Saber 1.40.8 and BeatLeader 0.9.33. Recording attaches to solo gameplay. The recorded map and characteristic must be installed to launch the replay. A playable review needs at least two movement frames. The repository remains source only while replay flow, runtime controls, and VR interaction continue through in-game validation.
